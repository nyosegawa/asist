# テーマは CSS 変数の値の組で表し、大きさを変えてよいのはカードの見出しだけにする

画面の見た目は、色、面、線、角丸、光のにじみ、背景の絵、カードの見出しの書体を、役割の名前を付けた CSS 変数から読む。部品は色を直接書かない。テーマはその変数の値の組で、future 以外のテーマは見出しの書体を除くすべての変数に自分の値を書く。書き忘れた値は future のまま残り、明るいテーマの中に暗い色が 1 か所だけ残っても、誰も気づかないからである。各カードは色味を 1 つだけ持ち、枠線、背景、影、強調色はテーマがそこから作る。テーマが変えてよい大きさは、カードの見出し(ラベル、タイトル、大きな数字)の書体と文字の大きさと揃え方だけで、本文の文字の大きさと余白はどのテーマでも同じにする。カードの s / m / l の切り替えは実測した高さに頼っていて、変えてよい範囲を見出しに絞れば、見切れの確認がテーマの数だけ増えても追いきれるからである。見出しで高さが変わるので、見切れの確認はすべてのテーマとすべての言語の組み合わせで行う。天気と時計のカードの絵は、どのテーマでも夜の景色のままにし、その上の文字は future の色で書く。

## 見送った案

- **テーマごとにカードのレイアウト(並び方)を変える。** カードの中の並びは各カードの JSX で決まっていて、テーマごとに JSX を分けることになり、s / m / l の高さもテーマごとに測り直すことになる。
- **画面の見切れは future だけで測り、カードだけをテーマごとに測る。** CI は数秒しか伸びないが、あとでテーマが画面の書体や余白を変えるようになったときに確認が漏れる。
- **天気の風景をテーマごとに描き直す。** 都道府県ごとに 48 枚あり、どれも夕暮れの光で描いてある。昼の見た目のテーマのためにすべてを作り直すことになる。

## 実測

- 見切れの確認(`npm run demo:fit`)は、テーマ 1 つで約 20 秒、4 テーマで約 31 秒だった(10 コアの Mac、2026-09-24)。テーマの切り替えはページを読み直さずに行うので、テーマの数に比例しては伸びない。

## 分かっている制約

- 中央の球、Dock のアイコン、球の周りに canvas で描く光の粒は、どのテーマでも future の見た目のままである。変えるには、テーマごとの絵と色が要る。
