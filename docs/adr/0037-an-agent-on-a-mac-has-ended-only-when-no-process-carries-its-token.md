# Mac では、Agent が終わったことを、トークンを環境に持つプロセスが一つも残っていないことで確かめる

claude と codex は、エージェントが動かすコマンドを、それぞれ別のセッションやプロセスグループで起動する。claude 2.1.276 の Bash ツールはシェルを `detached` で起動し、codex 0.137.0 はコマンドを自分のプロセスグループに入れる。そのため CLI のプロセスグループが空になっても、ビルドやテストのコマンドが残って worktree に書き続けることがある。一方、ASIST が起動のたびに環境変数 `ASIST_AGENT_EXECUTION_ID` に入れるトークンは、こうしたコマンドにも受け継がれる。そこで Mac では、停止のときに CLI のグループと、グループの外でトークンを環境に持つすべてのプロセスに信号を送り、グループが空で、トークンを持つプロセスが一つも残っていないときに、ジョブが終わったとみなす。CLI が自分で終わったときに残ったプロセスも同じように止めてから、worktree をコミットするか片付ける。再起動のあとの回収も、保存したトークンを持つプロセスをグループの外まで探して止める。止めきれなかった停止は、もう一度頼むと信号を送り直す。

## 見送った案

- **CLI のプロセスグループだけを見る。** 別のグループに移ったコマンドを数えないので、止めないまま worktree をコミットしたり消したりし、アプリの終了も許してしまう。
- **親子のつながりをたどる。** CLI が先に終わると、残ったコマンドは launchd の子になり、たどれなくなる。

## 実測

- 利用者のすべてのプロセスの環境を `ps` で読むのに、500 ほどのプロセスが動く Apple Silicon の Mac で約 50 ms かかった(2026-10-02)。main のスレッドで読むので、CLI のグループの確かめ(25 ms ごと)よりも間をあけて、500 ms ごとに読む。

## 分かっている制約

- 環境を消して起動し直したプロセス(`env -i` で起動したものなど)は、トークンでは見つからない。
- エージェントがジョブの中で起動して残した開発用のサーバーのように、自分では終わらないプロセスも、ジョブの終わりに止まる。
