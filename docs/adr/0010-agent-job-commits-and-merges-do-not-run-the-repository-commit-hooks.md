# エージェントのジョブの変更をまとめるコミットと取り込みでは、リポジトリのコミット用のフックを動かさない

worktree で隔離したジョブが終わると、ASIST はエージェントが残した変更を worktree の中で一つのコミットにまとめ、承認されればそれを利用者のリポジトリへ取り込む。どちらのコミットも write-tree、merge-tree と commit-tree で作業ツリーの外に作り、ブランチを動かすだけにする。作業ツリーは、worktree ではまとめたコミットの内容のまま変わらず、利用者のリポジトリでは取り込みのコミットへ fast-forward で進むだけになる。そのため、リポジトリの pre-commit、prepare-commit-msg、commit-msg、pre-merge-commit、post-commit のフックはどれも動かない。git commit に `--no-verify` を付けても止まるのは pre-commit と commit-msg だけで、prepare-commit-msg は動く。フックはふつう worktree とリポジトリで共通なので、worktree のコミットでも利用者のフックが動く。取り込みは、利用者のリポジトリの中で途中で止まってはならない。git merge で取り込むと、フックが失敗したときに取り込みが途中のまま残り、ジョブの変更がステージされた状態になる。そこで利用者が git commit すると、誰も確認していない変更がコミットされてしまう。worktree のコミットでフックが失敗すると、ジョブの変更は取り込みも確認もできないまま残る。また、フックの多くはコミットメッセージの形を確かめるもので、commitlint は「asist: …」というメッセージを拒み、npx を呼ぶフックは Finder から開いたアプリの狭い PATH では npx を見つけられない。そうしたリポジトリでは、フックを動かすかぎりジョブの変更を一度も取り込めない。

## 見送った案

- **フックを動かし、フックが拒んだら取り込みを取り消す。** リポジトリは元に戻るが、メッセージの形を確かめるフックや npx を呼ぶフックがあるリポジトリでは、取り込みが一度も成功しない。
- **worktree のコミットだけは git commit の `--no-verify` で作る。** prepare-commit-msg は止まらないので、そこで npx を呼ぶリポジトリでは worktree のコミットが毎回失敗する。

## 分かっている制約

- post-merge フックは fast-forward のときに動く。その結果は取り込みの成否に影響しない。
- pre-merge-commit フックでテストを走らせて取り込みを止める使い方は、ASIST の取り込みでは成り立たない。ASIST が取り込むのは、利用者が差分を見て承認した変更だけである。
