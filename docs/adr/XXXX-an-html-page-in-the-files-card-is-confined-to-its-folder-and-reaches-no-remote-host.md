# ファイルのカードで開く HTML のページは、そのページのフォルダの中だけを読み込み、外へは一切つなげない

ファイルのカードで開いた HTML のページ(`asist-file` で配る)には、そのページが入っているフォルダとその下だけを読み込ませ、ほかのフォルダのファイルも、外のサーバーも読み込ませない。送信の口もすべて閉じ、`fetch`、`sendBeacon`、WebSocket、外のスクリプト・画像・スタイル・フォントの取得、フレーム、ワーカー、フォームの送信、別アドレスへの移動のどれもできないようにする。これは `htmlPagePolicy` が組み立てる CSP で決める。`sandbox allow-scripts` でページの生成元は不定になり、`asist-file` は生成元ごとの読み取りを許さないという当初の想定だったが、この scheme は特権付きで CORS を有効にしているため、生成元が不定のページでも `crossorigin` の画像と canvas で許可フォルダのどの画像の画素も読め、`<script>` で別のファイルを実行してその中身も取り出せた。読んだものは当初 `connect-src https:` が許していたどの https のサーバーへも送れた。ページが許されるのは、自分のフォルダの画像・スタイル・スクリプトと、ページ自身が持つ data: だけにする。CSP の source はホストを必要とするが、ローカルのパスの `asist-file` URL にはホストがないので、空のホストの代わりに `*` を置き、パスでフォルダに閉じ込める。Windows の共有のときはサーバー名をそのままホストにする。

## 見送った案

- **これまでどおり、CDN からスクリプトやスタイルを読み込めるようにする(`script-src`/`img-src` などに `https:`、`connect-src https:`)。** レポートがグラフの部品を CDN から読むためという当初の許可だったが、外の https へ出す口はそのまま、読み取った別ファイルの中身を外へ送る口になる。「外へ一切つなげない」ことと「任意の https を読み込める」ことは両立しないので、外部の読み込みはやめ、ページは自分のフォルダの中で完結させる。

## 分かっている制約

- ページは外部の資源を読み込めないので、CDN のライブラリに頼るレポートは、部品を自分のフォルダに同梱しておくか、ページの中に埋め込む必要がある。
- フォルダへの閉じ込めは CSP のパスで行うので、同じフォルダの中にあるファイルどうしは、これまでどおり互いの画素や中身を読める。別のフォルダのファイルは読めない。
