# サブモジュールに触れたエージェントのジョブは ASIST では取り込まず、worktree を残して利用者に任せる

worktree で隔離したジョブの変更をまとめるコミットは、エージェントが worktree に残したものをそのままコミットし、サブモジュールの項目も .gitmodules も書き換えない。取り込みが利用者のブランチに加える変更、つまり利用者のいまの HEAD との合流点(merge base)からジョブのコミットまでの差分がサブモジュールに触れていると、ASIST はそのジョブを取り込まない。触れているとは、サブモジュールが指すコミットの変更、.gitmodules の変更、サブモジュールの追加や削除、ふつうのフォルダとサブモジュールの入れ替えのどれかがあることである。エージェントがサブモジュール自身の作業フォルダの中を変えたとき(中でのコミット、ファイルの編集や追加、初期化していないフォルダへの書き込み)も同じにする。worktree で初期化したサブモジュールのリポジトリは worktree の git フォルダの中にあり、worktree と一緒に消えるので、そこにあってその remote のどのブランチからもたどれないコミット(ブランチ、タグ、stash、reflog にだけ残るもの)も、サブモジュールの中の作業として扱う。サブモジュールは .gitmodules ではなく index の項目から探す。.gitmodules に載らないリポジトリもあるからである。worktree を聞かずに片付けるのは、差分にもサブモジュールの中にも失われうるものが何もないときだけにする。ASIST がジョブを片付け、差分を見せ、取り込むために読む差分と状態は、リポジトリの表示の設定に左右されず、正確な変更でなければならない。`submodule.<name>.ignore` や `diff.ignoreSubmodules` は git diff からも git status からもサブモジュールの変更を隠し、`status.showUntrackedFiles=no` は新しいファイルを隠し、`diff.external` や textconv は git diff の出力を別のものに置き換える。これらを上書きできるのはコマンドの引数だけなので、ASIST はどの呼び出しでも引数で上書きして読む。

そうしたジョブは worktree を残して取り込み待ちのまま置き、カード、取り込みの確認、ジョブの報告、get_agent_job で、サブモジュールに触れたので ASIST では取り込めないこと、利用者が自分でブランチを取り込むか、捨てられることを伝える。サブモジュールの中で作ったコミットは worktree の中の複製にしか無く、利用者のチェックアウトで git submodule update をしても取ってこられないので、先にその worktree から push する必要があることも伝える。捨てるとその複製も消えるので、会話からだけでなく、カードの「捨てる」でも確認画面を出す。取り込みのボタンと merge_agent_job は、確認画面を出す前に断る。エージェントがサブモジュールの中で作ったコミットは worktree の中の複製にしか無いので、そのコミットを指す項目を取り込むと、利用者のリポジトリは存在しないコミットを指す。また、取り込む前に見せる差分には「Subproject commit」の行が出るだけで、中で何が変わったかは見えない。そのため、ASIST が確かめられるのは「サブモジュールに触れたかどうか」までで、取り込むかどうかは中身を見られる利用者が決める。

## 見送った案

- **サブモジュールの項目と .gitmodules だけをジョブの開始時点や合流点の値に戻してコミットし、ほかの変更を取り込む。** コミットの中で項目を書き換えること自体が危ない。エージェントが利用者の main や別のブランチを取り込んだりリベースしたりしていると、利用者自身が進めたサブモジュールを取り込みが元に戻し、見せた差分にもそれが出ない。どの値に戻すかは片付けたときに開いているブランチで変わる。サブモジュールの `ignore` の設定は中の変更を隠し、worktree にしかない作業を聞かずに消してしまう。パスをサブモジュールに入れ替えた変更では、戻したあとのファイルが未コミットのまま残り、ジョブが取り込めなくなる。
- **サブモジュールの中の変更をサブモジュールのリポジトリへ移して取り込む。** 取り込みの確認画面で見せる差分にサブモジュールの中の変更が出ず、利用者が見ていない変更を利用者の別のリポジトリへ書き込むことになる。
- **サブモジュールの中だけが変わったジョブを、変更のないジョブとして worktree ごと片付ける。** エージェントのコミットの唯一の複製を、利用者に聞かずに消すことになる。

## 分かっている制約

- ジョブでサブモジュールが指すコミットを新しくする(依存を最新にする)変更は、ASIST では取り込めない。利用者がブランチを自分で取り込む。
- 版 3 の履歴で取り込み待ちだったジョブは、この確かめをせずに片付けられているので、読み込むときに片付け直す。
