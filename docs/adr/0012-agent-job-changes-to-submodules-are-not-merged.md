# エージェントのジョブがサブモジュールに加えた変更は取り込まず、取り込まないことを利用者に伝える

worktree で隔離したジョブの変更をまとめるとき、サブモジュールの項目(サブモジュールが指すコミット)と .gitmodules は、ジョブが始まったときのままにしてコミットする。サブモジュールの中のファイルの変更も、サブモジュールの追加や削除も取り込まない。取り込まなかったサブモジュールの名前は、取り込み待ちのジョブでは差分と一緒に見せ、ほかに変更のないジョブでは要約に書く。新しい worktree ではサブモジュールが初期化されておらず、エージェントが初期化してその中でコミットしても、そのコミットは worktree の中のサブモジュールの複製にしか無く、worktree を片付けると消える。サブモジュールが指すコミットだけを取り込むと、利用者のリポジトリは存在しないコミットを指すことになる。また、取り込む前に見せる差分には「Subproject commit」の行が出るだけで、サブモジュールの中で何が変わったかは見えないので、利用者が差分を見て承認するという取り込みの前提が成り立たない。

## 見送った案

- **サブモジュールの中の変更をサブモジュールのリポジトリへ移して取り込む。** 取り込みの確認画面で見せる差分にサブモジュールの中の変更が出ず、利用者が見ていない変更を利用者の別のリポジトリへ書き込むことになる。
- **サブモジュールに変更があれば、ほかの変更も含めて取り込みを止める。** サブモジュールの外の変更まで、続きのジョブでサブモジュールの変更を戻させるまで取り込めなくなる。

## 分かっている制約

- ジョブでサブモジュールが指すコミットを新しくする(依存を最新にする)ことはできない。
- 変更がサブモジュールの中だけだったジョブは、取り込む変更のないジョブとして worktree ごと片付けられ、その変更は残らない。
