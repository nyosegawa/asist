# ローカルの音声のモデルは、マイクが必要とするあいだだけ読み込む

音声認識(Qwen3-ASR)と MaAI と相槌の種類の判定は、声のエンジンのマイクが入っているあいだだけ動かし、マイクを切るとすぐに止める。読み上げの Irodori-TTS と Qwen3-TTS は、マイクを入れたときと、何かを読み上げるときに読み込み、マイクが切れているあいだは、マイクを切ってから、そして最後に読み込むか読み上げてから 5 分たったら止める。アプリを起動しただけでは読み込まず、Gemini Live で話すときも読み込まない。マイクを入れたら録音はすぐに始め、最初の書き起こしのほうがワーカーの準備を待つ。置いたままにすると、話しかけていないあいだも、音声認識を llama-server で動かしていた 2026-10-05 には、Apple M5 でメモリを約 5 GB、RTX 2080 で 8 GB のうち 3.5〜4 GB の VRAM を使い続けた。speech.cpp に移したあとも、音声認識だけで、Apple M5 ではメモリを 1.1〜2.5 GB、RTX 2080 では VRAM を 0.9〜2.7 GB 使う(ADR 0059)。一方で、読み込み直すのは下の実測のとおり 1〜3 秒で、マイクを入れてから最初に話しているあいだに済む。読み上げにだけ 5 分の猶予を置くのは、マイクを切ったまま文字で話すときやジョブの報告でも読み上げを使うからで、返事のたびに読み込み直すと、そのたびに声が遅れる。

## 見送った案

- **起動したときに読み込み、アプリを終えるまで置いておく。** 話しかけていないあいだも、上のメモリと VRAM を使い続ける。
- **マイクは入れたままにして、5 分会話がなければ解放し、VAD が話し始めを捉えたら読み込み直す。** 読み込み直しが 1〜3 秒で済むので、マイクに合わせるほうが決まりが簡単になる。マイクが入ったままだと、VAD を通った部屋の声やテレビの声のたびに読み込み直す。
- **マイクを切っているときは、読み上げも返事を言い終えるたびに止める。** 文字で続けて話すと、返事のたびに 2 秒ほど(ファイルが OS のキャッシュから追い出されていれば Windows で 5 秒ほど)読み込み直し、そのうち言語モデルの返事を待つあいだに収まらない分だけ声が遅れる。

## 実測

2026-10-05、アプリに同梱した speech.cpp のワーカーを起動してから、使えるようになるまでの時間。ファイルが OS のキャッシュにある状態で測り、括弧の中はディスクから読んだ 1 回目。Qwen3-ASR は、2026-10-07 に speech.cpp 0.7.1 のワーカーで測り直した値である。RTX 2080 では、マイクを入れてからワーカーが準備できたと出すまでの時間で、VRAM は `nvidia-smi` の GPU 全体の使用量のうち、マイクを切っているときの 1.64 GB を超えた分である。

| | Apple M5(32 GB)、Metal | RTX 2080(8 GB)、Vulkan |
|---|---|---|
| Qwen3-ASR | 1.7B で 0.56〜0.67 秒、0.6B で 0.37〜0.42 秒 | 1.7B で 1.6 秒(5.7 秒)、VRAM 2.27 GB。0.6B で 1.0 秒(2.5 秒)、VRAM 0.93 GB |
| Qwen3-TTS 0.6B | 2.2〜2.5 秒 | 2.1 秒(4.7 秒)、VRAM 1.4 GB |
| Qwen3-TTS 1.7B | 3.1〜3.3 秒 | 測っていない |
| Irodori-TTS | 1.9〜2.1 秒 | 1.7 秒(5.3 秒)、VRAM 2.1 GB |

## 分かっている制約

- GPU のドライバーの不具合などでモデルを起動できないことは、アプリを起動したときではなく、マイクを入れたときに初めて分かる。
- 新しい版のアプリや GPU のドライバーを入れたあとの最初の読み込みは、GPU のプログラムを作るので 12〜16 秒かかり、その回の最初の書き起こしはそれだけ待つ。
- VOICEVOX と AivisSpeech のエンジンは、読み上げる文ごとには起動しないので、この決まりでは止めない。
