# 言語の設定を、画面の言語、会話の言語、地域の3つに分ける

画面の言語は画面に出る文とエラーを、会話の言語は話す言葉、聞き取る言葉、プロンプト、記憶を書く言語を、地域は天気とニュースの取得元、既定の通貨、日付と数値の書き方を決める。3つは別々に変えられ、アプリを動かしたまま変えても次のターンから反映する。日本に住んで英語で話す人が、画面と会話を英語にしたまま、天気は気象庁のものを見られるようにするためである。初回セットアップでは言語を1つだけ尋ね、それを3つの初期値にする。最初から3つを別々に尋ねると、ほとんどの人には意味の分からない質問になるからである。

会話の言語を途中で変えても、それまでの記憶と履歴は書かれた言語のまま残す。記憶の検索に多言語のモデルを1つだけ使うのは、言語の混ざった記憶をそのまま探せるようにするためである。天気は、地域が日本なら気象庁から、それ以外なら Open-Meteo から取る。

## 見送った案

- **言語を1つにまとめる。** 上の使い方ができなくなる。
- **日付と数値の書式に画面の言語をそのまま使う。** 英語の画面は必ず12時間表記になり、ドイツに住む人の英語の画面で「18:05」「22/09/2026」と書けない。書式は画面の言語に地域の習慣を組み合わせて決める。

## 分かっている制約

- 書式のデータ(CLDR)に「日本の英語」のような組み合わせが無い場合は、書式が地域に従わず、言語だけで決まる書き方になる。
- 右から左に書く言語は入れていないので、画面の左右を反転させる作りは無い。
