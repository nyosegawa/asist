# メモはメモリに持って検索し、ASIST の外での変更はメモのフォルダを監視して取り込む

メモのサービスは、最初に呼ばれたときにメモのフォルダを全部読んでメモリに持ち、一覧、検索、1 件の読み出しにはそこから答える。ASIST が保存したり消したりしたメモは、そのときに持っている内容を書き換える。ほかのエディタで書き換えたメモや、Finder やエクスプローラーで足したり消したりしたメモは、フォルダの監視(`fs.watch`)で知り、ファイルを読み直して取り込み、変わったメモだけを画面に伝える。検索のたびにフォルダを全部読むと、メモが 4 万件のときに 1 回の検索が 2 秒を超え、`search_notes` が時間切れになって、モデルが保存したばかりのメモを確かめられなかったからである。また、画面は起動時に一覧を一度読むだけだったので、ASIST の外で足したり消したりしたメモが次の起動まで一覧に出ず、外で消したメモは一覧から消すこともできなかった。

## 見送った案

- **検索のたびにフォルダを読む(これまでのやり方)。** ほかのエディタでの変更はいつも見えるが、メモが数万件になると検索が時間切れになる。
- **全部のファイルの更新日時だけを先に調べ、新しい順に読んで、検索の上限の 10 件が見つかったところで止める。** よく出る語なら安く済むが、当たるメモが少ない語では結局全部を読む。

## 実測

2026-10-02、Apple M5、ほかの作業で負荷が高い状態(load average 10〜20)で、生成した 4 万件のメモ(平均 659 バイト)を Electron 43 の Node で読んで測った。

- 検索 1 回:フォルダを読むやり方で 0.85〜7.8 秒、メモリに持つやり方で 16〜40 ms。
- 最初にフォルダを全部読む時間:1.7〜2.6 秒。起動して画面が一覧を読むときに 1 回だけかかる。
- メモリに持つ量:ヒープで約 28 MB。
- ASIST の外でメモを書いてから、その変更を画面に送るまで:84〜103 ms。
- 何も変わっていないときにフォルダ全体を調べ直す時間(一覧とファイルごとの stat):0.25〜0.46 秒。
- フォルダごと内容の違うコピーに置き換えたとき:4 万件を読み直し、1 回の送信(11 MB)で画面に送るまで 3.9 秒。

## 分かっている制約

- macOS の FSEvents は、通知を取りこぼしたときにそのことをフラグで知らせるが、Electron 43 の Node(libuv 1.52)はそのフラグの付いた通知を捨てる。取りこぼした変更は、そのメモが次に変わるか、次に ASIST を起動するまで画面に出ない。
- Windows では、監視が通知を受け取るバッファ(4 KB)があふれると名前のない通知が来るので、そのたびにフォルダ全体を調べ直す。
