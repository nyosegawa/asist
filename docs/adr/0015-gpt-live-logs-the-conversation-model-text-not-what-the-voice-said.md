# GPT-Live では、会話ログと画面に会話のモデルの文を残し、GPT-Live が話した言葉は残さない

声のエンジンが GPT-Live のとき、会話ログには、会話のモデルが受け取った発話や文字の入力と、会話のモデルが書いた返事の文を書き、画面にも会話のモデルの文を出す。GPT-Live の出力の転写は使わない。GPT-Live は指示に従うかぎり、会話のモデルの文を自分の言葉で読むか、挨拶、相槌、聞き返しのように中身のない言葉を言うだけなので、残す意味のある中身はすべて会話のモデルの文にある。そのうえ GPT-Live は、一つの返事を読み終えたことを知らせない。読むあいだに 1.5 秒以上黙ることもあれば、続けて渡した文を間を置かずに読むこともあるので、読み上げの転写のどこまでがどのターンの返事かを決める手がかりがない。Gemini Live は会話のモデルを使わず、転写のほかに会話の文がないので、転写からログを書く。

## 見送った案

- **読み上げの転写を区切りごとに、その文を渡したターンに振り分ける。** 黙った時間で区切っても、渡した文の長さと照らし合わせても、読み上げの区切りと返事の区切りが合わない。間が空くと返事の残りが別のターンになり、返事のすぐ後に始まったジョブの報告が返事のターンに入り、GPT-Live の相槌でユーザーの発話が途中で切れた。会話のモデルへの次の依頼には、同じ返事が二度入ったり、アシスタントの発言で終わったりした。

## 分かっている制約

- 読み上げの途中でユーザーが割り込んでも、GPT-Live はどこまで読んだかを知らせないので、ログには返事の全文が残る。途中で止まったと記録されるのは、会話のモデルのターンそのものが止められたときだけである。
- GPT-Live が指示に反して自分で中身のある答えを言ったときは、その答えはログにも画面にも残らない。
- GPT-Live が会話のモデルに任せずに受け答えしたユーザーの発話は、次に会話のモデルに渡す発話や文字の入力の前に並べて一緒に渡し、そのターンの入力として記録する。GPT-Live が聞き返してから任せたときも、聞き返す前の発話が会話のモデルに届く。その代わり、GPT-Live がすでに答えた挨拶や相槌も、会話のモデルには次の依頼と一緒に届く。
- 任せる合図のときに新しい発話の転写がなく、任されなかった発話があるときは、その発話のあとに「上の発話は聞き取れたが、合図と一緒に新しい発話は届いていない。依頼は最後の発話かもしれないし、聞き取れなかった別の発話かもしれない」という注を付けて渡し、答えるか聞き返すかは会話のモデルに任せる。遅れて来た合図と、相槌のあとの転写が届かなかった依頼は、時間では見分けられないからである。任されなかった発話もないときは、転写が届いていないとだけ伝える。
- 任されなかった発話のうち、会話が止まってからセッションを閉じるまでの時間より前に言ったものと、マイクをオフにする前に言ったものは、会話のモデルに渡らず、ログにも残らない。そのあいだにセッションがどう閉じたか(会話が止まったのか、提供元や通信が切ったのか)には関わらない。時間がたってからの依頼に古い発話を付けると、ユーザーが済ませた話に会話のモデルが答えてしまうからである。
