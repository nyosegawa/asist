# ウィンドウを閉じたときと最小化したときはマイクを切り、ウィンドウを戻してもマイクは切ったままにする

ウィンドウを閉じて Mac のメニューバーや Windows の通知領域に入れたときと、Dock やタスクバーに最小化したときは、マイクを切る。マイクが切れると音声認識と MaAI と相槌の種類の判定はすぐに止まり、読み上げのモデルも、言いかけの返事が終わったあとの watchdog の確認で止まるので、隠したアプリがメモリや GPU のメモリを使い続けない。隠したアプリが部屋の音を拾い続けることもない。ウィンドウを戻してもマイクは切ったままにし、ショートカットキーで呼び出したときだけ、これまでどおりマイクを入れる。カードを見るためだけにウィンドウを戻したときに、マイクが勝手に入らないようにするためである。ウィンドウが隠れているあいだに終わったジョブは、OS の通知でその場で知らせ、声での報告はウィンドウを戻すまで待つ。マイクが切れていて、報告を聞いても答えられないからである。

## 見送った案

- **トレイに入れてもマイクは入れたままにする。** トレイから話しかけられるが、モデルを置いたままにするか、VAD が話し始めを捉えるたびに読み込み直すことになり、部屋の声やテレビの声でも読み込み直す。
- **ウィンドウを戻したら、隠す前のマイクの状態に戻す。** カードを見るためだけに戻したときにも、マイクが入る。
- **最小化はトレイと分けて、マイクを入れたままにする。** Windows ではウィンドウをしまうのに最小化を使うことが多く、そのあいだ VRAM が空かない。
- **ウィンドウが隠れていても、終わったジョブをその場で読み上げる。** 読み上げのモデルを読み込み直して声で知らせても、マイクが切れているので答えられない。

## 分かっている制約

- トレイに入れたまま声で話しかけることはできない。
- ほかのウィンドウの後ろに隠れているだけのときは、マイクを切らない。閉じたときと最小化したときだけを、ウィンドウのイベントで見分ける。
