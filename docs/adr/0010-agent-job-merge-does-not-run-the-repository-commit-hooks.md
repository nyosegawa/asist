# エージェントのジョブの変更を取り込むときは、リポジトリのコミット用のフックを動かさない

worktree で隔離したジョブの変更を利用者のリポジトリへ取り込むとき、取り込みのコミットは merge-tree と commit-tree で作業ツリーの外に作り、作業ツリーはそのコミットへ fast-forward で進めるだけにする。そのため、リポジトリの commit-msg、prepare-commit-msg、pre-merge-commit のフックは動かない。worktree の中でエージェントの変更をまとめるコミットも、`--no-verify` で作っている。取り込みは、利用者のリポジトリの中で途中で止まってはならない。git merge で取り込むと、フックが失敗したときに取り込みが途中のまま残り、ジョブの変更がステージされた状態になる。そこで利用者が git commit すると、誰も確認していない変更がコミットされてしまう。また、取り込みで動くフックの多くはコミットメッセージの形を確かめるもので、commitlint は「asist: …」というメッセージを拒み、npx を呼ぶフックは Finder から開いたアプリの狭い PATH では npx を見つけられない。そうしたリポジトリでは、フックを動かすかぎり取り込みが毎回失敗する。

## 見送った案

- **フックを動かし、フックが拒んだら取り込みを取り消す。** リポジトリは元に戻るが、メッセージの形を確かめるフックや npx を呼ぶフックがあるリポジトリでは、取り込みが一度も成功しない。

## 分かっている制約

- post-merge フックは fast-forward のときに動く。その結果は取り込みの成否に影響しない。
- pre-merge-commit フックでテストを走らせて取り込みを止める使い方は、ASIST の取り込みでは成り立たない。ASIST が取り込むのは、利用者が差分を見て承認した変更だけである。
