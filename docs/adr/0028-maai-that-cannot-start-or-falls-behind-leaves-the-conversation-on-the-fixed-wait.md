# MaAI を起動できないときや処理が遅れたときは、設定した無音の長さで会話を続け、そのことを一度だけ知らせる

「声」の画面で MaAI をオンにしているのに、マイクをオンにしたときに MaAI の worker を起動できなかったら(Python 環境やモデルが無い、worker が終了した、読み込みが時間内に終わらない)、マイクは止めずに、設定した無音の長さで話し終わりを判断して会話を続ける。原因は main のログに書き、利用者には、MaAI をオンにしてから最初の一度だけ、MaAI を起動できず設定した無音の長さで判断していることを知らせる。worker が動いていても、処理が会話の音に追いつかず、話し終わりの推定が 500 ms より前の音についてのものになったら、その推定は使わず、追いつくまで同じく設定した無音の長さで判断する。そうした古い推定が 5 秒続けて届いたら、マイクをオンにしているあいだに一度だけ、MaAI の処理が遅れていて、追いつくまでは設定した無音の長さで判断していることを知らせる。

ASIST は失敗を隠して別の動きに切り替えないことにしているが、これはその例外である。MaAI は話し終わりの判断を速くするためのもので、無くても会話はできる。MaAI のためにマイクを止めると、会話そのものができなくなる。一方で、知らせずに切り替えると、利用者は MaAI が動いていると思ったまま、返事が遅いことの理由が分からない。起動できないことは、利用者が直すまでマイクをオンにするたびに同じように起こるので、MaAI をオンにしてから一度だけ知らせる。遅れはそのときのコンピュータの忙しさで決まるので、マイクをオンにするたびに改めて判断する。5 秒は、worker が一度止まってから追いついただけのときには届かず、負荷が続いて遅れたままのときにはすぐに届く長さとして選んだ。

## 見送った案

- **マイクをオンにする操作ごと失敗させる。** MaAI を直すか、設定でオフにするまで、会話ができなくなる。
- **推定が古くなったらすぐに知らせる。** ほかの処理が重なって一度止まった worker は、Mac では 1 秒ほどで追いつくので、知らせが出たときにはもう MaAI の推定を使っていて、知らせの内容が当たらない。
- **マイクの音が届くたびに、最後に使えた推定からの時間で遅れを判断する。** 推定を送らなくなった worker も遅れていることになり、終了して起動し直しているだけの worker についても、処理が遅れていると知らせてしまう。

## 実測

- 2026-10-02、負荷の高い Mac で、音を実時間で渡した worker は 30 秒に 248 個の推定を送った。実時間の約 3 分の 2 の速さで、推定は 401 ms より間をあけずに届き続けたが、中身は最大で 7.5 秒前の音についてのものだった。この速さでは、負荷がかかってから約 1.5 秒で推定が 500 ms より古くなり、MaAI が 8 秒分たまった音を捨てるまで古いままなので、知らせは負荷がかかってから約 6.5 秒で出る。
- 1 フレーム(80 ms)の処理は、Mac で約 31 ms、Core i9-9900K の Windows 11 で中央値 59.8 ms だった(2026-09-27)。この速さから計算すると、worker が 2 秒止まったあと推定が 500 ms 以内に戻るまで、前者は約 1 秒、後者は約 4.4 秒かかり、どちらも 5 秒に届かない。

## 分かっている制約

- 会話の途中で worker が終了し、起動し直せなかったときは、ログに書くだけで、その場では知らせない。次にマイクをオンにしたときの起動も失敗すれば、まだ知らせていない場合に限って知らせる。
- 遅れは worker が送ってくる推定だけで判断する。推定をまったく送らなくなった worker は、遅れとしては知らせない。
- 相槌と頷きのモデルだけが遅れたときは知らせない。そのあいだ、相槌は文字だけで判断する。
- MaAI がオフのとき、日本語以外で会話しているときは、起動しないので何も知らせない。
