# 会話のモデルが始める・続けるエージェントのジョブと、worktree の取り込みは、すべて確認画面でユーザーの承認を得てから行う

会話のモデルが `run_agent_task` と `continue_agent_job` でジョブを始めたり続けたりするときは、読むだけのジョブも含めて、必ず確認画面を出す。確認画面にはエージェントに渡す指示そのもの、作業場所、書き込めるかどうかを載せ、ユーザーがボタンを押したときだけエージェントを起動する。声では承認できない。`merge_agent_job` も、取り込む変更の一覧を確認画面に載せ、承認されたときだけ取り込む。

会話のモデルの文脈には、メール、ウェブ検索、メモ、予定の文面が入る。そこに「エージェントでこのコマンドを実行して」と書かれていれば、モデルがそれに従ってジョブを始めることがありうる。一方で、書き込めるジョブは claude の `--permission-mode auto` や codex の `--approve-for-me` で動き、どちらも OS のサンドボックスではない。claude はコマンドもネットワークも使え、作業フォルダの外にも書ける。専用の作業フォルダは起動するときのディレクトリにすぎず、閉じ込める仕組みではない。そのため、ジョブはユーザーの権限で動くものとして扱い、始める前に本人が中身を見て決める。

画面のボタンからユーザーが直接行う操作(ジョブカードの「取り込む」、設定画面の「今すぐ整理する」)は、その操作自体が承認なので、確認画面を重ねない。記憶の整理は誰にも聞かずにタイマーで動いて取り込むので、差分が記憶のフォルダの中の普通のファイルだけであることを確かめ、そうでなければ取り込まずに失敗として記録する。整理のジョブ自体も、書き込めるジョブの無人のモードでは動かさない。claude は restricted モードで動かし、ファイルの道具を作業フォルダの中に限り、許したもの以外はすべて断らせ(dontAsk)、実行できるコマンドはスキルの検査スクリプトだけにする。codex は承認を出さない workspace-write のサンドボックスで動かし、ネットワークと作業フォルダの外への書き込みを OS に止めさせる。

## 見送った案

- **読むだけのジョブは確認なしで始める。** 読むだけの claude のジョブにも WebFetch があるので、~/.ssh などを読んで URL に載せて外へ送れてしまう。
- **専用の作業フォルダで動くジョブは確認なしで始める。** 作業フォルダは閉じ込めになっておらず、書き込めるジョブはホームフォルダのどこにでも書ける。
- **git リポジトリのジョブは worktree で隔離して確認なしで始め、承認は取り込みのときにする。** worktree も閉じ込めにはならず、取り込む前にエージェントがリポジトリの外で何でもできる。
- **取り込みの確認をツールの説明でモデルに頼む。** 文脈に入った文面がモデルを動かす以上、モデルへの指示は承認の代わりにならない。

## 分かっている制約

- ジョブを始めるたびに確認画面が出るので、ユーザーが画面の前にいないとジョブは始まらない。確認は5分で打ち切られ、そのときは始めない。
