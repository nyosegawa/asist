# Mac では、ASIST が終わると、動いている Agent のプロセスグループに SIGTERM を送る

Mac の Agent は、起動用のシェルが `exec` で CLI に置き換わったプロセスグループで動く。シェルは `exec` の前に、同じグループに見張りのプロセスを 1 つ残す。見張りは、ASIST だけが反対側を持つパイプを読んで待ち、ASIST が落ちたり強制終了されたりしてパイプが閉じると、グループに SIGTERM を送る。Windows では launcher が ASIST の終了で Job を止めるので、どちらの OS でも、ASIST が終わったあとに Agent が作業を続けることはない。見張りが無いと、CLI は出力を読む相手がいなくなっても作業を続ける。そのあいだは画面から止められず、ログも残らず、次に ASIST を起動して回収するまで誰も見ていない状態になる。

## 見送った案

- **次の起動の回収に任せる。** 作業が終わるまで、または利用者が ASIST を起動し直すまで、誰も見ていない Agent が書き続け、そのあいだのログは残らない。
- **シェルから ASIST の PID を一定の間隔で確かめる。** 確かめるたびに CLI のグループで `sleep` が動き、ASIST の PID が別のプロセスに再利用されると取り違える。
- **Windows と同じように、Mac にも起動用のプログラムを作る。** Mac には Job Object が無いので、シェルの見張りと同じことしかできず、署名する実行ファイルが 1 つ増える。
- **見張りが SIGTERM のあと、時間をおいて SIGKILL も送る。** 見張りは自分に届く SIGTERM を無視し、CLI がまだ動いているかを確かめなければならない。claude は SIGTERM で 1 秒以内に止まり(下の実測)、SIGTERM で止まらなかったものは次の起動の回収が SIGKILL まで送って止めるので、そこまではしない。

## 実測

- claude 2.1.276 を起動したプロセスを強制終了すると、見張りが無いときは、CLI は実行中のコマンドを終え、モデルにもう一度問い合わせ、次のコマンドも実行してから、強制終了の約 28 秒後に終わった。見張りがあるときは、CLI は 1 秒以内に終わり、実行中のコマンドも完了しなかった(2026-10-02)。

## 分かっている制約

- 見張りが SIGTERM を送るのは CLI のプロセスグループだけである。CLI が別のセッションやグループで動かしているコマンドは、SIGTERM を受けた CLI が止めるのに任せる。それでも残ったものは、次の起動の回収が止める。
