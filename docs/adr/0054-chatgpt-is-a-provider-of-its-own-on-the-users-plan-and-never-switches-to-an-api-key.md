# ChatGPT のプランで会話する経路は、OpenAI とは別の提供元「ChatGPT」にし、API キーに切り替えない

ChatGPT の Plus と Pro のプランで会話する経路は、OpenAI の提供元の中の切り替えにはせず、「ChatGPT」という独立した提供元にして、画面では OpenAI のすぐ下に並べる。プランで使える経路は、API キーの経路と、要求の形(store を false にしてストリームで受ける、関数ツールを namespace にまとめる、max_output_tokens を送らない)も、料金の数え方(トークンごとの金額がなく、プランの使用量に含まれる)も違う。一つの提供元にまとめると、モデルの選択、料金のページ、エラーの文のどれにも、どちらの経路かの条件分岐が入る。ログインは、OpenAI が利用者のコンピュータで動くオープンソースのアプリ向けに示している手順(Sign in with ChatGPT)を ASIST の中に書いて行う。使用量の上限に達したときや、プランが対象外のときも、API キーがあってもそちらへ自動では切り替えない。利用者の知らないうちに API の料金がかかるからであり、OpenAI もアプリが黙って別の支払い方法に移らないよう求めている。要求は Responses API の WebSocket で送り、終わった接続を次の要求のために残す。

## 見送った案

- **OpenAI の行の中で、API キーと ChatGPT のプランを切り替える。** 選んだ方式ごとに、モデルの一覧、要求の形、料金の数え方を分けることになり、上の条件分岐がすべて OpenAI の提供元の中に入る。
- **OpenAI の公式の DevKit を同梱する。** 非商用のライセンスなので、MIT ライセンスで配る ASIST には入れられない。
- **HTTP で送る。** プランの経路は、要求ごとに応答の始まりまでの待ちが長く、下の実測のとおり WebSocket で接続を使い回すより遅い。

## 実測

2026-10-05 に、この Mac と一つの ChatGPT のアカウントで測った。

- 使い捨ての手順で、約 2,700 トークンの指示を付け、思考の深さを low にして、最初の文字が届くまでを 6 回ずつ測った中央値。プランの gpt-5.6-terra は HTTP で 2190 ms、WebSocket で 1567 ms。gpt-5.6-luna は HTTP で 2785 ms、WebSocket で 1065 ms。API キーの gpt-5.6-terra は HTTP で 845 ms、WebSocket で 658 ms。
- 開発版のアプリで、ツールを使わない短い会話を送ると、最初の一言までは、プランの gpt-5.6-terra で 1.9〜3.1 秒、同じモデルを API キーで使うと 1.2〜2.3 秒だった。つなぎの一言の JSON は、プランの gpt-5.6-luna で 1.6〜2.1 秒で返った。
- 3 回続けた会話は、同じ WebSocket の接続を使い回した。

## 分かっている制約

- プランを使えるのは Plus と Pro だけである。ID トークンにはプランの種類が入っていないので、ASIST からは Plus か Pro かを知る方法がなく、使えないことは要求の失敗で初めて分かる。
- プランの経路は、同じモデルを API キーで使うより、最初の一言が 1 秒ほど遅い。
- Plus の 5 時間ごとの使用量の上限は、ChatGPT 自身やほかのアプリと共有する。
- プランで送った会話が OpenAI の学習に使われるかは、OpenAI のヘルプに書かれていない。
