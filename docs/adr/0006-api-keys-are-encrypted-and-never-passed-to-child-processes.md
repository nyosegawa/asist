# API キーは暗号化して保存し、Agent の CLI を含むどの子プロセスにも渡さない

設定画面で保存した API キーは、メールのパスワードと同じく safeStorage で暗号化して保存し、平文のファイルには書かない。暗号化が使えないときは保存せずにエラーにする。キーは SDK のクライアントに直接渡し、main の環境変数には入れない。子プロセス(codex と claude、Python のワーカー、音声エンジン、ネイティブのヘルパー、git)を起動するときは、環境変数にある provider のキーも取り除く。Agent のジョブは、プロンプトインジェクションを受けるとユーザーの権限でコマンドを実行できるので、環境変数に入っているキーはそのまま外へ送られうる。codex と claude は、それぞれの CLI の側で設定した認証で動かす。

## 見送った案

- **これまでどおり `userData/.env` に平文で保存する。** 同じユーザーで動くどのプロセスからも読める。古い `.env` の移し替えはせず、キーは設定画面で入れ直してもらう。

## 分かっている制約

- ASIST から claude のジョブを使うには、claude の側に API キーを設定しておく必要がある。Claude.ai のサブスクリプションでのサインインは、ASIST からの利用には使えない。
- 開発版とインストールしたアプリでは暗号化の鍵が違うので、一方で保存したキーはもう一方では読めない。開発時は実行ディレクトリの `.env` のキーが優先される。
