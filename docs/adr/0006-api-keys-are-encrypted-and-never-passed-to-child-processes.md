# API キーは暗号化して保存し、Agent の CLI を含むどの子プロセスにも渡さない

設定画面で保存した API キーは、メールのパスワードと同じく safeStorage で暗号化して保存し、平文のファイルには書かない。暗号化が使えないときは保存せずにエラーにする。キーは SDK のクライアントに直接渡し、main の環境変数には入れない。子プロセス(codex と claude、Python のワーカー、音声エンジン、ネイティブのヘルパー、git)を起動するときは、環境変数にある provider のキーも取り除く。Agent のジョブは、プロンプトインジェクションを受けるとユーザーの権限でコマンドを実行できるので、環境変数に入っているキーはそのまま外へ送られうる。ChatGPT でのログインのトークンも、同じく暗号化して保存し、どの子プロセスにも渡さない。codex と claude は、それぞれの CLI の側で設定した認証で動かす。claude には、Claude のプランでも API キーでも、利用者が claude 自身の手順でサインインする。ASIST の中に ChatGPT のログインはあるが、Claude のログインは作らず、claude の認証情報も読まない。Anthropic は、ほかのアプリが Claude.ai のログインを提供することや、その認証情報やセッションのトークンを集めたり保存したりすることを認めていないからである。

## 見送った案

- **これまでどおり `userData/.env` に平文で保存する。** 同じユーザーで動くどのプロセスからも読める。古い `.env` の移し替えはせず、キーは設定画面で入れ直してもらう。

## 分かっている制約

- macOS では、開発版とインストールしたアプリで暗号化の鍵が違うので、一方で保存したキーはもう一方では読めない。開発時は実行ディレクトリの `.env` のキーが優先される。
- Windows の safeStorage は DPAPI で、暗号化の鍵を userData(`%APPDATA%\asist`)の `Local State` に、その利用者なら誰でも解ける形で置く。そのため、同じ利用者で動くプロセスなら、どれでも保存したキーを取り出せる。プロンプトインジェクションを受けたジョブが自分でキーのファイルを読みに行くことは、Windows では防げない。開発版とインストールしたアプリは同じ userData を使うので、一方で保存したキーをもう一方でも読める。開発版で暗号化した文字列を、別の Electron のプロセスが同じ userData から復号できることを確かめた(Windows 11、2026-09-27)。
