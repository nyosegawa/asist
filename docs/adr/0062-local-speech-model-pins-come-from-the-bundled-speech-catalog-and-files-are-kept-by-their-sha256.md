# ローカルの音声のモデルの固定は同梱する speech のカタログから読み、ファイルは中身の SHA-256 のフォルダに置く

ローカルの音声のモデルのファイルの固定(リポジトリ、リビジョン、ファイル名、大きさ、SHA-256)は、ASIST のコードに書かず、起動したときに同梱する speech と同じ版のカタログのファイルを一度だけ読む。speech.cpp のリリースは、そのカタログのファイルで確かめてから出すので、speech.cpp を上げればファイルの固定も一緒に上がり、2 か所を合わせる手間も、合わせ忘れもなくなる。ASIST が持つのは、どのモデルを出すか、その並び、ラベル、認識できる言語、おすすめ、Irodori-TTS の声、クレジットの提供元とライセンスである。これらは画面のあちこちで同期的に使い、speech.cpp のリリースとは別の理由で変わる。ファイルは `speech-models/<owner>--<name>/<SHA-256>/<ファイル名>` に置き、リビジョンは取得する URL を作るためだけに使う。speech.cpp 0.8.2 のキャッシュも、Hugging Face のキャッシュも、llama.cpp も Ollama も、ファイルを中身のハッシュで見分ける。speech.cpp のカタログはモデルをリポジトリの最新のコミットで固定するので、モデルカードだけを直したコミットでも固定が動く。リビジョンのフォルダに置くと、そのたびに中身の同じファイルを取得し直すことになる。0.8 のカタログでは、Qwen3-ASR と Qwen3-TTS の 4 つ(6.5 GB)がそうなっていた。

0.8 より前の ASIST が `<owner>--<name>/<リビジョン>/<ファイル名>` に置いたファイルは移さず、ADR 0058 のとおり、どの固定にも無いものとして起動したときに消す。公開した 0.7.0 が固定したファイルは、どれも 0.8 のカタログに無い別のリポジトリのものなので、移せるものが無い。

## 見送った案

- **同梱した speech を実行し、`speech models --json` から読む。** Windows の speech.exe は Vulkan のランタイムを直接読み込むため、ランタイムが無いと一覧を返すだけでも起動できず、クラウドの音声を使う ASIST まで起動できなくなる。

- **ASIST が自分のコードに固定を持ち続ける。** speech.cpp を上げるたびに、カタログと同じ値を ASIST にも書くことになり、合わせ忘れると、speech.cpp が確かめていないファイルを使う。
- **カタログの固定を、それぞれのファイルを最後に変えたコミットにする。** カタログはモデルごとにリビジョンを 1 つ持つので、同じリポジトリに別の型のファイル(ビット数の低いもの)を足すと固定が動き、中身の変わらないファイルを取得し直す。
- **リビジョンのフォルダのまま置く。** モデルカードを直すたびに、中身の同じファイルを取得し直す。
- **前の ASIST がリビジョンのフォルダに置いたファイルを、SHA-256 を確かめて今の置き場所に移す。** 移せるのは 0.7.0 のあとの開発版が置いたファイルだけで、公開した版の利用者には移せるものが無い。この Mac で 10.26 GB を確かめるのに 5.1 秒かかり、そのあいだウィンドウが開かない(2026-10-09)。

## 分かっている制約

- 同梱した speech のカタログに ASIST が使うモデルが無いと、ASIST は起動しない。speech.cpp を上げるときは、`tests/fixtures/speech-models.json` もその版のカタログのファイルに替える。
- 0.8 より前の ASIST に戻すと、中身のフォルダを固定に無いものとして消すので、取得し直すことになる。
