# エージェントのジョブは、index の設定が git に見させないファイルも含めて、worktree をディスクにあるとおりにコミットする

worktree で隔離したジョブが終わると、ASIST はエージェントが残した worktree を、ファイルがディスクにあるとおりにコミットする。git には、ファイルを見ずに済ませるための設定がある。リポジトリの core.ignoreStat が有効だと、git は worktree を作ったときにすべてのファイルに assume-unchanged を付ける。エージェント自身も update-index で assume-unchanged や skip-worktree を付けられる。fsmonitor のフックは変更の通知を取りこぼすことがあり、core.checkStat=minimal や core.trustctime=false は、大きさと更新時刻を戻した書き換えを見逃す。これらをそのまま信じて読むと、編集が見えないままジョブは変更なしとして片付けられ、worktree と一緒に編集が消える。そこで ASIST は、これらの設定を切った git で読み、ディスクにあるファイルは、付いている設定にかかわらず、あるとおりに数える。assume-unchanged はファイルを見ないための目安にすぎないので、ディスクに無いファイルからも外し、そのファイルは削除として数える。skip-worktree は、sparse checkout が取り出さないファイルに git が付ける設定でもあるので、ディスクに無いファイルからは外さず、削除とも数えない。sparse checkout がそのファイルを取り出さないのなら、変わっていないファイルである。それ以外、つまり sparse checkout の範囲の中にあるときや、sparse checkout が切られているとき、その範囲を書いたファイルが無いときは、エージェントが削除を隠したのか、取り出していないだけなのかを見分けられないので、コミットせずに worktree を残し、理由をジョブのログに出す。取り出していないファイルの場所にエージェントがほかのファイルを置き、コミットするとそれらが削除される場合も、同じようにコミットしない。読むときはジョブの index の複製を使い、ジョブの index は書き換えない。index を書き換えるのはコミットだけで、そのときに、ディスクにあるファイルを隠していた設定を外す。取り込みの前に利用者のリポジトリが変わっていないかを確かめるときも、同じ設定を切った git で読み、利用者の index は書き換えない。fsmonitor が見逃した利用者の編集を、取り込みが黙って上書きしないためである。

## 見送った案

- **リポジトリと index の設定をそのまま信じて読む。** 編集が見えないまま worktree を消すので、エージェントの作業が失われる。
- **sparse でない worktree では、skip-worktree をすべて外す。** そうした worktree で skip-worktree を付けるのはエージェントだけとは限らない。sparse checkout をリポジトリ全体の設定で使っていて、利用者が自分の作業ツリーでそれを切ったときや、エージェントが取り出し直さずに切ったときは、取り出していないファイルがすべて削除としてコミットされる。
- **sparse の worktree でも skip-worktree をすべて外す。** 取り出していないファイルがすべて削除としてコミットされる。
- **sparse checkout のリポジトリではジョブを片付けない。** sparse のリポジトリでは、どのジョブも取り込めなくなる。
- **範囲の中にあって無いファイルを削除として扱う。** 範囲を変えて取り出し直していないだけのときに、エージェントがしていない削除を取り込み待ちにしてしまう。
- **読むたびにジョブの index から設定を外す。** 取り込みの前の確認のたびに index が変わり、ほかの git が index をロックしていると確認が失敗する。sparse checkout が一時的に切られているあいだに確認すると設定が外れたまま残り、戻したあともすべてのファイルが削除に見える。
- **worktree で git sparse-checkout reapply をしてから読む。** worktree のファイルを書き換えるので、エージェントが消したファイルが戻り、エージェントが残したものとは違うものをコミットする。

## 分かっている制約

- 取り出していないのか削除したのかが分からないファイルがあるジョブは、利用者が worktree で取り出し直すか、削除として扱うように直すまで片付かない。
- エージェントがファイルを消したあとで、そのファイルを外すように sparse checkout の範囲を狭めると、git がそのファイルに skip-worktree を付けるので、削除はコミットに入らない。git 自身もそのファイルを変わっていないものとして扱う。
